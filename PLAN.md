## 3. Агрегация transactions → signal-level признаки

Обозначения: `d` — время в днях от транзакции до `signal_sanasi 00:00`; **B** (burst) = d < 10 мин.
**Окна:** B · W1 (10 мин ≤ d < 1 дн.) · W7 · W30 (без B) · W30–90 · W90–180 · ALL (всё кроме B) · TOTAL.
**Ячейки:** всё · kirim / chiqim · 4 типа · 8 «тип × направление» (15 ячеек).

## 4. Валидация — фиксируется после подтверждения

**Схема: RepeatedStratifiedKFold, 5 фолдов × 3 повтора (seed 42, 43, 44), разбиение по сигналам (одна строка = один `signal_id`).**
Метрика: OOF ROC-AUC каждого повтора → среднее ± std, плюс AUC по фолдам.

**Почему не time-based split.** Test перемешан с train по всем 24 месяцам (P1), таргет стабилен (P2). Случайное стратифицированное разбиение воспроизводит ровно тот сценарий, по которому нас оценят. Time-split, как в IEEE-CIS (там test строго после train), мерил бы экстраполяцию во времени, которой в нашем тесте нет, и отнимал бы данные у обучения (E001).
**Почему не GroupKFold.** Ключа группы нет, связать сигналы нельзя (C14, E002).
**Опора на Kaggle.** В соревнованиях, где test из того же распределения, перемешанный K-fold давал CV ≈ LB: AmEx «CV 0.792 LB 0.793» (cdeotte), Elo «variations observed on the CV were found to be quite similar to the variations on the LB» (fabiendaniel). Group/time-сплиты там применяли только когда test лежал в будущем (IEEE, HC-2024).
**Adversarial validation не делаем.** Она обучает классификатор на признаках test, а CLAUDE.md запрещает использовать test для отбора признаков. Сходство train/test уже показано описательно (C2, C17).
**Страховка на случай, что проверяющие перезапустят ноутбук на другом скрытом наборе:** вторичная диагностика *time-forward* (обучение на сигналах ≤ 2026-06, проверка на 2026-07…12). Для решений не используется, служит только тай-брейкером между почти равными вариантами. Date-признаки выключены по умолчанию.

**Защита от утечек**
1. *По signal_id:* агрегаты строятся только из транзакций своего сигнала, сплит — на уровне сигналов. Модель уровня транзакций, если появится, обучается только с GroupKFold по `signal_id` вложенно внутри train-фолда.
2. *По времени:* признак использует только собственную историю сигнала (≤ `signal_sanasi`), никаких популяционных статистик по датам.
3. *Статистики:* всё, что «обучается» (пороги-квантили, z-нормализация, PCA, отбор признаков, калибровка, тюнинг), делается fit только на train-фолде внутри цикла CV. Для финального прогноза fit идёт на всём train, test только transform/predict.
4. *Early stopping* на валидационном фолде даёт лёгкий оптимизм: число деревьев фиксируется по среднему best_iter и перепроверяется на новом seed-повторе.
5. *Отбор признаков* идёт внутри CV, итоговый набор перепроверяется на новом seed-повторе (защита от selection bias).
6. Строки после полуночи сигнала (§1) оставляем, ведь это часть выданной истории, та же в test и без связи с таргетом. Отдельных признаков «есть ли пост-сигнальные транзакции» не делаем.

**Правило принятия эксперимента (предлагаю):** изменение принимается, если средний OOF-AUC по 3 повторам вырос **≥ +0.0010 и вырос в каждом из 3 повторов** (парное сравнение на тех же фолдах). Иначе изменение отклоняется и логируется. Основание: SE AUC ≈ 0.0066 при 2 405 позитивах (Hanley–McNeil, AUC≈0.6). Порог один раз пересмотрю после замера шума baseline, но только с вашего согласия.
**Лидерборда нет** (одна официальная отправка) → все решения принимаются только по CV.

## 5. Модели и ансамбль

| Модель | Стартовые параметры | Зачем |
|--------|--------------------|-------|
| **M1 LightGBM** | lr 0.01–0.03, num_leaves 7–31, min_child_samples 50–300, feature_fraction 0.1–0.5, bagging 0.8, λ2 5–50; число деревьев подбирается по CV и фиксируется. DART — только с фиксированным числом деревьев (early stopping с DART не работает) | основная рабочая лошадь; сильная регуляризация как в AmEx (ambrosm: `reg_lambda=50, min_child_samples=2400, colsample_bytree=0.19` на 458k строк). Диапазоны для 14k строк — моя экстраполяция, не проверено |
| **M2 CatBoost** | depth 4–6, lr 0.03, l2_leaf_reg 5–20, rsm 0.5, od_wait 300 | устойчив на шумных данных малого размера |
| **M3 XGBoost** | hist, max_depth 3–5, eta 0.02, subsample 0.8, colsample 0.5, min_child_weight 10–50 | разнообразие для ансамбля |
| M4 LR + сплайны (GAM-подобная) | QuantileTransformer → SplineTransformer → L2-LogReg | эффекты монотонные и пологие (P8) → аддитивная модель может быть конкурентной и даёт разнообразие |

- **Отбор признаков — null importance** (HC-2018, ogrellier, рецепт сверен с исходником): LightGBM `boosting_type='rf'`, `nb_runs = 80` перемешиваний таргета, score = `log(1e-10 + gain_actual / (1 + p75(gain_null)))`. Порог выбирается по repeated CV, весь отбор внутри train-фолдов. Дополнительный фильтр — знак одномерного AUC стабилен во всех фолдах.
- **Тюнинг:** Optuna на полном CV (никаких подвыборок — CLAUDE.md), ≤ 50 trials на модель, финальная проверка на новом seed-повторе.
- **Ансамбль:** rank-average OOF-предсказаний M1–M4 (как AmEx 1st: взвешенная смесь 0.3/0.35/0.15/0.1). Веса: равные или подобранные на OOF повтора A и проверенные на повторе B; подобранные принимаются только по правилу §4. Stacking — только если побьёт rank-average по тому же правилу. Каждая GBDT × 3–5 seed.
- **Фаза 2b (если позволит время) — модель уровня транзакций** (AmEx 1st, S3–S5): LightGBM на строках-транзакциях с меткой сигнала, та же разбивка на фолды по `signal_id`. OOF-скоры агрегируются по сигналу (mean / max / q90) и идут признаками в модель уровня сигнала. Риск утечки: признаки train-фолдов получены моделями, видевшими валидационный фолд. Поэтому один раз сравниваем со строго вложенной версией.
- **Выход:** Platt-калибровка на OOF (строго монотонна → AUC не меняется) → вероятности в [0, 1]. Проверка файла: 6 000 строк, уникальные ID ровно из `test_signals.csv`, нет NaN, 0 ≤ p ≤ 1, колонки `signal_id,ehtimollik`, имя `team_<TEAM_ID>.csv`.

## 10. Реализация Фазы 2 (детали, не меняющие схему валидации §4)

- **Оценочная схема не менялась:** StratifiedKFold 5 × 3 (seed 42/43/44), фолды сохранены в `artifacts/folds.parquet`, решения только по правилу §4.
- **Тюнинг и выбор порога отбора** (Optuna, порог null importance, C/knots у LR-сплайнов) делаются на **отдельном четвёртом повторе seed 100**, никогда на оценочных; затем выбранная конфигурация проверяется на 3 оценочных повторах по правилу §4. Так оценочные повторы не «видят» подбор гиперпараметров.
- **Число деревьев** фиксируется (без early stopping на валидационном фолде): для B0 — по среднему best_iter (E009), после тюнинга — по среднему best_iter на повторе seed 100.
- **Строки данных не удаляются:** `src/data.py` проверяет `len(tx) == len(raw)`; burst / ALL — это разметка окон, а не фильтрация.
- **Test** используется только через `transform`/`predict`: перцентили test-предсказаний считаются по ECDF train-OOF, Platt обучается на train-OOF.
- **Раунд 2 ablation:** после тюнинга все семейства, отклонённые в раунде 1 (нетюнингованная модель, 140 деревьев), перепроверены против тюнингованной базы тем же правилом §4 — отдельными строками лога.

### 10.1 Итоги Фазы 2 (все цифры — в EXPERIMENTS_LOG.md)
- **Финал:** равновесный rank-average LightGBM (F1+F2+F7, базовые параметры, 140 деревьев) + LR-сплайны (C=0.0003), Platt на train-OOF → **CV ROC-AUC 0.6469 ± 0.0007** (r42 0.6465 / r43 0.6479 / r44 0.6463). Ноутбук воспроизводит сабмит бит-в-бит (E068).
- **Принято по §4:** F7 контрасты (E019), LR-сплайны в ансамбль (E062).
- **Отклонено по §4:** fz, fx, fp, ft, F4, F3, F5, F6 (раунды 1 и 2), null-importance отбор, тюнинг LGBM (обе целевые), 5 seed, tx-модель (2b), XGBoost и CatBoost в ансамбле, подобранные веса, stacking.
- **Отступление от порядка §8:** шаг 2b (tx-модель) выполнен до ансамбля, чтобы ансамбль собирался уже из окончательного набора; раунд 2 ablation выполнен против базы f1+f2+f7 (модель не изменилась, т.к. тюнинг отклонён).

### 10.2 Итоги Фазы 3 (подходы, предложенные после Фазы 2)
- **Финал:** одиночная LightGBM (базовые параметры, 140 деревьев) на **F1 + F7 + fi (разности уровней между ячейками) + fx (exp-агрегаты)**, Platt на train-OOF → **CV ROC-AUC 0.6528 ± 0.0009** (r42 0.6527 / r43 0.6539 / r44 0.6517); было 0.6469 ± 0.0007.
- **Принято по §4:** fi (E073, +0.0046); fx после смены базы (E077, +0.0014); удаление F2 по LOO (E110, +0.0011). Прирост fi целиком дают разности уровней (E074: без них −0.0045), произведения не вносят вклада (E075).
- **Отклонено по §4:** kNN target-mean, отношение плотностей классов, гистограммы, ранги/Yeo-Johnson, монотонные ограничения, расширенный тюнинг, XGB/CatBoost/LR-сплайны в ансамбле с новой LightGBM.
- **Не выполнено:** увеличение числа повторов CV для пограничных экспериментов — это изменение схемы валидации §4, по CLAUDE.md требует явного согласия.
